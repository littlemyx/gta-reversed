# SYSTEMIC-9 (strcpy_s / strncpy_s into fixed game buffers) - 2026-10-30
Problem: the standalone build turns a *_s rejection into a fatal exception (Fixups::OnInvalidParam); the port used *_s where the exe copies with plain strcpy/strncpy, so an exactly-full 8 (or 10 / 16) char name crashed the run build.
Sweep: every strcpy_s / strncpy_s / strcat_s in source/ is in .notes/asm_sweep/STRCPY_S.tsv (file, line, function, dest size, exe function, verdict). 26 sites fixed in 11 commits, the rest are ok (local/formatted buffers that cannot overflow on game data).
Sites fixed (exe form): CRunningScript::ReadTextLabelFromScript 0x463D50 (strncpy(buf, src, n); the long-label inline form 0x463F30 is a verbatim memcpy; `count == dest` was rejected by strncpy_s), CRunningScript::SetName, CAudioZones::RegisterAudioBox/Sphere 0x508240/0x5081C0, CSaveGarage Copy*Garage 0x5D3020/0x5D30C0, CStats::LoadStatUpdateConditions 0x559860, COnscreenTimer::AddClock/AddCounter/AddCounterCounter 0x44CD50/0x44CDA0/0x44CE00 (strncpy 10), DrawCommands + TextCommands + TheScripts.h label copies, CText::LoadMissionText 0x69FBF0, CTaskComplexUseScriptedBrain ctor 0x6358B0, CVehicleModelInfo::SetGameName, CCutsceneMgr::LoadCutsceneData_overlay 0x5B13F0.
Intentional differences from the exe: the exe's unbounded strcpy writes the NUL one byte past the member (into the next field, or padding); the port uses strncpy(dst, src, sizeof dst), so an exactly-full name stays unterminated and nothing is written past the member. Readers: Garage/Stats/Text/OnscreenTimer/TheText.Get keys are length-bounded or hash-based on the following in-struct field (same layout as the exe, offsets are VALIDATE_OFFSET'd). Residual risk: CCutsceneMgr::ms_cutsceneName (detached global char[8], formatted with "{}" in 6 places) and CText::m_szMissionName rely on the byte after the array; an 8 char cutscene name would read into whatever follows (the exe has a NUL there). No shipped cutscene/mission name is known to need it besides the 8 char mission names (read with string_copy(size)).

It is a live C2dEffectPedAttractor (ent->GetRandom2dEffect(EFFECT_ATTRACTOR) + cast_if_present of a live entity; the event path requires m_entity (ref-cleared) and IsEffectActive).
