## Win32 untouched
All hooks are `#ifdef NOTSA_PORTABLE` or portable-only files. `w0a_guardlines.py check --base HEAD(e8d04fac)`: TEXT OK for SDLWrapper.cpp, WinMain.cpp, WinPs.cpp, VideoMode.cpp, Pad.cpp, Pad_SDL.cpp. Fixups.cpp: the edit is inside the `#elif defined(NOTSA_STANDALONE_RUN)` branch behind `#if ... && !defined(NOTSA_PORTABLE)`, dead whenever NOTSA_PORTABLE is undefined (the tool does not model #elif; not compiled with wine cl). New files are in source/portable/** (glob never seen by the Windows build) and tests/tools.

## Not done / open
* Rumble (CPad::ShakeDur/ShakeFreq are not driven on any platform), gamepad button remapping UI beyond the game's own, 2nd-pad PAD2 untested with a device.
* Real mouse/keyboard by a human, real gamepad hardware, window moved between a Retina and a 1x display (SDL_EVENT_WINDOW_DISPLAY_SCALE_CHANGED is not handled: modes stay in the pixels of the first display), live window resize by dragging (SDL_EVENT_WINDOW_RESIZED is still unconsumed upstream).
* Keyboard layout: letters follow the layout (like Win32 VK codes), not the physical position, so AZERTY users get Z/Q/S/D from the game's WASD defaults moved.
* `vendor/librw` showRaster still calls SDL_GL_SetSwapInterval(1) when the flag is set - never reached now (PresentPace strips it), other callers of showRaster (smoke test) keep SDL's behaviour.
* Menu cursor starts at the clamped corner (1280,720 points) until the first real motion; the game's own CentreMousePointer warp covers it in normal flow.
