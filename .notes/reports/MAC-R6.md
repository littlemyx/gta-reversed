## What
* **v-flip rule (R-4 hand-over) resolved in librw gl3, no shader change**: with `rw::gl3::d3dTexelOrder` (set by RwEngineOpen) the default and skin instance callbacks store `1-v` (new `instTexCoordsGL`, gl3pipe.cpp; gl3skin.cpp calls it) so the unchanged shader flip samples row v of the top-first raster; gl3matfx's env matrix flips its v scale (`normal2texcoord.up.y = +0.5`) so env maps sample D3D's `0.5 - 0.5*ny`. Default 0 = upstream behaviour. Im2D / Im3D keep their own rule (NotsaGl3TextureNeedsVFlip). gl3 files only (GL3 source list; not in any Win32 build).
* `portable/render/pipelines_gl3.{h,cpp}`: RwShimPipelineEnsure / Shutdown (stubs removed from rw_stubs_gl3.cpp), `NotsaGl3StockPipelinesReady`; logs "R-6: stock gl3 pipelines default=1 skin=1 matfx=1". The pipelines themselves are created by librw (driver open + Skin / MatFX plugin hooks); atomics with `pipeline == nullptr` use the driver default.
* **NVC crash root cause**: R-2 left `CCustomBuildingDNPipeline::ObjPipeline == nullptr`; `AtomicHasNVCPipeline` is `atomic->pipeline == ObjPipeline`, true for EVERY stock atomic -> NVCPipelineProcess read DayColors == nullptr (PROLOG1 LoadScene crash). Fix (CustomBuildingDNPipeline.cpp, guarded `#ifndef NOTSA_PORTABLE ... #else`): portable = pipeline-id tag CUSTOM_BUILDING_DN_PIPELINE_ID set by CustomPipeAtomicSetup AND Night/DayColors present. NVC is **implemented, not a fallback**: NVCPipelineProcess writes the blended colours into the prelit array under RpGeometryLock(PRELIGHT); librw's default instance callback re-uploads exactly the colour stream on the next draw (lockedSinceInst). Proven in the test (Lock/Unlock changes the drawn colours twice). Cost: whole VBO glBufferData per update (exe-side rate limiting s_Magic stays).
* Test: tests/portable/rw_pipeline_gl_test.cpp + tools/portable/run_pipe_test.sh (compiles the renderer-neutral shim standalone/rw/*.cpp minus the excluded D3D files, stream.cpp / rwtexdict.cpp need the game PCH and are replaced by 2 test stubs). **PIPE RESULT OK, 55 checks**: texture orientation (2x2 texture, 4 quadrants top-first, texel (200,100,50) draws (200,100,50): v-flip + texel order), prelit, NVC lock mechanism x2, MODULATEMATERIALCOLOR, ambient 0.4 -> 102, directional 0.5 -> 128, no-LIGHT ignores lights, alpha test (alpha-0 texel discarded), blend, z test both orders, cull back/none, linear fog (170,170,255 at 1/3), matfx env up/down orientation, glGetError clean after each block. Real data from gta3.img / player.img (read in place): sw_diner1, farmhouse, bakery_sfse, cityhall_sfs (prelit buildings, 9-21 textured materials, coverage 3-9 %, 341-2198 colours), male01, wmycr (skinned, textured), chinos / afro / country (player.img clothes, skinned), infernus (15 atomics, 18 matfx materials): all coverage > 0.7 %, no GL error.
