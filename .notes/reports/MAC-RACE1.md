# MAC-RACE1: load-dependent new-game crash (CWorld::Process -> CPhysical::RemoveAndAdd) — 2026-10-24
Status: REPRODUCED and chain traced to a garbage animation translation of a cutscene object; the writer of the garbage is NOT yet identified, nothing fixed. No source change committed (diag patch only, see below).

## Reproduction (works)
* Load = N workers looping `clang++ -O2 -c Collision.cpp/Automobile.cpp` (compile_commands flags, PCH stripped, -o /dev/null), 18-28 workers, load average 30-90. `yes` busy loops (load up to 60) do NOT reproduce (10/10 pass): needs the allocator/cache pressure of compiles, not just CPU contention.
* Route: menu -> New Game, then wait 40 s (ng2.txt). The crash is ~23 s after the cutscene starts (csTimer 22.37 s = the very end of PROLOG1; fault at frame ~8200 of the process), so the old 14 s wait never saw it. Baseline exe (HEAD 820fbc9c): 12 crashes in 22 loaded runs (~55 %), 0 of 5 unloaded; stop/cont freezes (0.4 s every 1.5 s, frame step clamped to 3.0) do NOT reproduce => not a long-frame / time-step problem (hypothesis b rejected).
* Harness: .notes/reports/MAC-RACE1_harness/ (loop.sh, cload.sh, run1.sh, boot.sh = mac_boot_run.sh with DYLD pass-through, slowio.c = pread latency interposer: also no repro, hypothesis a not supported).
* CAVEAT for anyone reusing it: from ~10:20 on every run stopped starting the new game (menu ignores the injected keys, 0 "Loading the Game" lines; the known-good 09:37 exe also fails) — the session was probably not frontmost/unlocked (pmset: UserIsActive 0). Check `grep -c "Loading the Game" run.out` > 0 before trusting a pass. All "0 crashes" counts after 10:20 in my log are invalid; only runs with PROLOG1 in the log count.

## Chain (diag build, 6 crashes captured)
1. `CPhysical::RemoveAndAdd` -> `new CEntryInfoNode` returns null (pool 500 exhausted in ONE call; pool use is normal ~241 before). Cause: bound rect = (-1.84467e19 .. +1.84467e19) (= sqrt(FLT_MAX)), sector range saturates int32 => the loop allocates until the pool is empty. (My first range check overflowed int32 and hid this: use int64.)
2. Rect comes from `CTempColModels::ms_colModelCutObj[i]` (cutscene model 302 = the taxi, once also 300 = ped), rewritten EVERY frame by `CCutsceneMgr::UpdateCutsceneObjectBoundingBox` from `RwV3dLength(frame chain) + atomic radius`. A wheel-mesh RwFrame of the cutscene clump had matrix pos (4.7e27, 4.5e30, 1.76e19), and its raw bytes read "\0bump_front_" (12 bytes, an anim sequence / bone name) = pos, once "D:\alienbrai" (a DFF/anim name string).
3. The frame position is written by `FrameUpdateCallBackT` (RpAnimBlend.cpp) from `CAnimBlendNode::I_Update`; every offender had `cur == frames-1` (last key frame), `prev` = cur-1 or cur-2, `remaining == 0`, assoc curTime 22.2867 (end of the cutscene anim), flags 0x4041, uncompressed (skinned bones with 625/635 frames and the taxi nodes with 42/27 frames). Returned translation was e.g. (2.9e29, 1.8e28, 8.03): x/y text-like garbage, z sane. No out-of-range KF index (OOB check never fired).
4. => the KEY FRAME DATA at the end of the PROLOG1 sequences contains foreign bytes (heap memory reused by names), i.e. use-after-free / overwrite or uninitialised tail of the keyframe block; whether it reaches the renderer depends on the heap contents (so on thread interleaving of the CdStream/audio threads' mallocs) and on whether the cutscene runs far enough to evaluate the last key frame. Under no load the same bytes are apparently clean / the cutscene ends one frame earlier.
5. Not the cause: CdStream race (no repro with 30 ms..2 s pread latency, and the crash site is not streaming data), time step, frame-freeze, pool exhaustion as primary cause, F6 NaN bone (that was the RtAnimInterpolator pointer store, already fixed).

## Where to go next (not done: ran out of the 100 min budget, the last 40 min lost to the harness problem above)
* Decisive experiment (diag.patch has half of it): snapshot a checksum of every PROLOG1 sequence's key frame block right after `CAnimManager::LoadAnimFile` in `LoadCutsceneData_postload` and verify it every 20 frames + at the BAD moment (RaceSnapshotAnims/RaceVerifyAnims in diag.patch, built, never got a valid crashing run). Changed checksum => find the writer (suspects: `CAnimManager::UncompressAnimation` LRU cache eviction `RemoveUncompressedData` of an anim that is still playing — its own TODO says it corrupts in-use anims; `RemoveLastAnimFile` popping the wrong block when an IFP block is initialised after the cutscene's; `CMemoryMgr::MoveMemory`). Unchanged checksum => the loader leaves the tail uninitialised (ANPK `SetNumFrames`/`GetDataSize` vs the bytes read for KRT0/KRTS), compare with the exe's allocation size.
* MallocScribble=1 had no visible effect (the game's allocator is not libc malloc) — a poisoned-free in CMemoryMgr::Free under NOTSA_PORTABLE would make this deterministic.
* A symptom guard (skip RemoveAndAdd/clamp the cut-object radius when the rect is absurd) would stop the crash but hides the corrupted animation; not committed.
