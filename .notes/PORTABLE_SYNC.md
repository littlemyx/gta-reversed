## MAC-RR2 (2026-10-24): F6 root cause = RtAnimInterpolatorSetCurrentAnim pointer stores over the game's 0x1C-byte interp frames
`0x7CD5A0` stores keyFrame1/keyFrame2 at +0/+4 of each interpolated frame; the game's scheme (rwID_RPANIMBLENDPLUGIN, interpKeyFrameSize 0x1C = {q,t}) has no header, so the exe overwrites q.x/q.y with heap addresses (float ~1e-38: benign on x86, the reason R* never noticed; the game's IsFixBugs branch in RenderWare/rw/rtanim.cpp skips it). On Win32 nothing to fix. For the RR Win32 trace (RR-3): the first skeleton update of a new ped reads q = (addr1, addr2, 0, 1) as floats; if addresses are >= 0x3F800000 (not in a normal 32-bit process) it would matter. If the Windows oracle diverges at a ped's first frame by ~1e-38, this is why. Portable: pointers not stored for this scheme.
