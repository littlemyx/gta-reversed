### TheCamera: ctor 0x51A450 disassembled (dis.py), repo differed in 25 fields + 3 matrices
The exe ctor: `CPlaceable::CPlaceable`, vector-ctor of `m_aCams[3]` (0x517730 = `CCam::Init`), `m_aPathArray[4]` (0x5097B0, ptr = 0), `CMatrix` members touched only at +0x40/+0x44 (**no identity**), `m_aCamTweak[5]` (ctor 0x50E470: `{-1, 1.0f, 1.0f, 0}`), `m_nShakeType = 1`, `m_matrix = &m_mCameraMatrix`, then `InitialiseScriptableComponents` (0x50D2D0). Fixes:
* `CamTweak` got the member initialisers of 0x50E470 (image: `ffffffff 3f800000 3f800000 0`).
* 23 member initialisers of `CCamera` that are the values of the exe's `CCamera::Init` (0x5BC520: `rep stosd` over +0x18.., then stores: `m_bJustInitialized`, `m_bLookingAtPlayer`, `m_nLongestTimeInMill = 5000`, `m_nCarZoom = 2`, the 4 two-player modes, `m_fFractionInterToStopMoving = 0.25f`, ...) are NOT the constructor's state (image = 0); they never applied before because `TheCamera` was a `StaticRef`. Reset to `{}`; `m_mCameraMatrix{ Identity }` -> `{}`.
* `CCam::Init` (0x50E490, also the CCam ctor): was missing the leading `gIdleCam.Reset(true)` (0x50E49F), and `m_fMaxRoleAngle` was 20 degrees; the exe stores 0x3D0EFA35 (2 degrees, unused elsewhere) and `m_fPlayerInFrontSyphonAngleOffSet` 0x3EB2B8C3 (the repo's `DegreesToRadians(20)` is ...C2). Both bit-exact now. The same function writes the globals `gPlayerPedVisible / gbCineyCamMessageDisplayed / gCameraDirection / gCameraMode / gLastTime2PlayerCamera*` and `TheCamera.m_bCinemaCamera` = this is the "writes outside the object" of the audit: all constant-initialised to the same values in the repo, verified by the dump.
* Self pointer `m_matrix` (+0x14): deviation row.
* **Finding (not fixed, outside C3)**: the repo's `CCamera::Init` (0x5BC520, hooked) has no `rep stosd` and none of the ~40 field stores the exe has (5000, 4, 6, 2, 2, ...), so after a (re)Init those fields stay as before; the removed member initialisers are the table of the missing values. Open item for a later camera pass.
* Static-init order: `TheCamera` (Camera.cpp) -> `CCam::Init` x3 -> writes `gIdleCam` (IdleCam.cpp, `Reset(true)` = same fields as `CIdleCam::CIdleCam` -> `Reset(false)` plus `CPad::GetPad()->LastTimeTouched = 0`) and the constant-initialised camera globals. All writers store identical values, so the link order of the TUs does not matter; nothing reads another dynamic-init object.
