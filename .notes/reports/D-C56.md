### Left address-mode on purpose
* `s_MemoryHeapBuffer` (`char[16384]`, 0xC8E0C8, MemoryMgr.h): `common.h` (B20, off limits for stream C) aliases the same address as `PC_Scratch`. Converting only one of the two names would create a stray; it is a plain zero scratch buffer, so B20 converts both together. `g_Heaps` (the heap descriptors) is converted.
* Nothing else: every object of the two families is a real global.

## Problems found and fixed at the root

**Does not compile / wrong object (found by building, none of it was in the triage)**
* Namespace-scope `static inline NOTSA_GLOBAL(...)` in headers (g_procObjMan, g_boneNodeMan, TheText, g_Heaps, gCrossHair) would be one object per TU in a real build (the verifier printed "dumped twice"): now `NOTSA_GLOBAL_HDR`.
* Incomplete types at the point of the definition: Hud.h (+Sprite2d.h), World.h (+PlayerInfo.h, which now includes PlayerPedData.h), CWeaponInfo::aWeaponInfo (an array of its own incomplete class: `NOTSA_GLOBAL_DECL` in the class, `NOTSA_GLOBAL_DEF` at the end of WeaponInfo.cpp; the member is public now because the registration is at namespace scope), `CSector() = default` (the deleted copy members suppressed the implicit default ctor).
* `CScriptResourceManager() = delete`, `WaterCreatureManager_c::~WaterCreatureManager_c()` declared but never defined (link error: the exe's atexit wrapper 0x856A80 / dtor 0x6E3F20 only runs member dtors, now `= default` in the cpp).
* `FireManager`: `s_Unk_B728E0` in MissionCleanup.cpp is `gFireManager.m_nMaxFireGenerationsAllowed` (+2400); `static_assert`s with absolute addresses in Radar.cpp / MemoryMgr.cpp became offsets.
* 10 files had CRLF line endings in the tree: normalised.

**Repo defaults that are not the exe's boot bytes**
* The exe leaves these arrays zero (TheScripts x12, ScriptResourceManager, 3d markers: static ctor writes nothing, `Init()` fills them later) but the repo's NSDMIs give `-1` ids, `true` flags, `-100.f` volumes: `ExeZero<T>()` (bit_cast of zero bytes, or default-construct + memset for types with `EntityRef`); `tScriptBrainWaitEntity` array: `m_ScriptBrainIndex = 0`.
* `CAESound` (the root of the audio, garage and water-cannon mismatches: 724 B in AudioEngine, 3900 B in AESoundManager, 13 B per rain / weather / explosion entity, 650 B in aGarages, 39 B in aCannons): the exe's default ctor 0x446FE0 is empty and every `CAEAudioEntity::m_tempSound` / each of the 300 sounds of `CAESoundManager` sits in .bss. In the detached build `CAESound()` leaves a sound that lies inside the exe image all-zero (`notsa::IsInExeImage`, `GetModuleHandle` + `SizeOfImage`); sounds on the heap or stack still get the repo defaults. Same for the `CAECollisionAudioEntity` history / list (`255`, `-1`, `TOTAL_NUM_COLLISION_SURFACE_TYPES`) and `CAEPedlessSpeechAudioEntity` (`PED_TYPE_UNK` / `VOICE_UNK`), whose exe ctors (0x4E6070 ...) store only the vptr. The `#ifdef NOTSA_GLOBALS_DETACHED` branches keep option-OFF code unchanged.
* `CAEStreamTransformer::table` (16 B): the "ctor" at 0x4F1750 is `Initialise()`, so the key is now the member initialiser.
* `AERadioTrackManager` is .data bytes in the exe, not a constructed object: zero, `m_HwClientHandle = -1`, and the two flags that FrontEndMenuManager's static ctor stores into it (`m_bBassEnhance`, `m_bRadioAutoSelect`; the only writes the ctor 0x574350 makes into other globals besides g_fx+0x54 (D-C34's), 4 constant-initialised floats / bools and itself) are part of the initial value, so the result does not depend on which of the two globals is initialised first.
* `ms_effectPairs`: the exe's pair ctor 0x6FA770 / 0x6F9EB0 stores -1 to every field except `Effects[1].PartnerTask` (stays 0). `ClearEffectPairs` already documents this slip ("BUG: The original forgets ..."); the boot value now has the 0.

**CMenuManager ctor vs exe 0x574350 (asm evidence)**
* `m_bShowSubtitles` default: `SetDefaultPreferences` display branch, `mov byte ptr [esi+0x44], al` with `al = 0` at 0x573BF1: **false** (the repo had `true`).
* `m_vMapOrigin`: `0x5744AE mov [esi+0x68], 0x43A00000` (320) and `0x5744B5 mov [esi+0x6C], 0x43600000` (224 = `DEFAULT_SCREEN_HEIGHT / 2`); the repo had `APP_MINIMAL_HEIGHT / 2` = 240. Both are fixes toward the exe in every mode.

**rand-derived bytes (observable: `Game.cpp` hands the menu station to `AudioEngine.InitialiseRadioStationID`; the first camera shake uses `m_vel`)**
* The exe's `rand()` is the MSVC LCG with seed 1; 19 draws happen in static init (18 for the 6 CHandShaker, then 1 for the menu). Image values: `m_vel` of the 6 handshakers = draws (z, y, x) of 1..18 (`CVector::Random` draws z first: element 0 has z = 41/32767 * 0.0001, y = 18467/32767 * 0.0002, x = 6334/32767 * 0.0002), station = 2.
* Reproduced exactly instead of a deviation row: `MakeExeHandShakers()` builds the 6 elements in place (`CHandShaker(const CVector&)`, prvalue elements, so the `CMatrix` copy ctor does not run) with the 18 bit patterns; the menu ctor pins the station to 2 (`#ifdef NOTSA_GLOBALS_DETACHED`, `#line` keeps the option-OFF lines). `standalone_deviations.tsv` needs no row from this slice.
