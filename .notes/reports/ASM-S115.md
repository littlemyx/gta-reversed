Fixes (exe range, one line each):
- cfff88417 CSprite2d::Draw2DPolygon (0x7285B0-0x72863A): the shade-mode render state (7) is set to rwSHADEMODEFLAT (bytes `6A 01 6A 07`: push 1, push 7); the port set rwSHADEMODENASHADEMODE (0). Later 2D draws inherit the state, so every user of the polygon draw left a different shade mode behind.
- 30ab7f23b CSprite2d::DrawBarChart (0x728640-0x728A8C): the add-bar (progressAdd != 0, used by the HUD health/armour style bars) has left = max(x - 1, currX - (int8)progressAdd) (`movsx; fisub; fcom; test ah, 0x41`). The port carried a FIX_BUGS-commented expression `max(x-1, currX - add < 0 ? 127 : add)` that is not guarded by `#ifdef FIX_BUGS` and put progressAdd itself (a small number) in the left coordinate, so the bar covered everything from x-1 to currX. Same function: unclamped currX = x + width * (progress * 0.01f) (the port multiplied (width * progress) * 0.01f); only the lower progress clamp exists in the exe (progress < 0 -> 0, NaN stays), the port also clamped to 100 (visible only in the unused percentage text); currX = (unclamped < endX) ? unclamped : endX (NaN gives endX); Bottom and Right border rects are built flipped like the exe (Bottom: bottom = y + h, top = y + h - border; Right: left = endX, right = endX - border) - the quad covers the same pixels.
- 5e240afcf CSprite2d::DrawCircleAtNearClip (0x727D60-0x727FC8): the step is (float)(360 / angle) with an INTEGER division (`mov eax, 360; cdq; idiv`), the port divided in float. Only angles that do not divide 360 differ (both callers use 15). Left as is: the exe derives the second vertex angle as a1 + float(step index) in one x87 expression and indexes the sin table directly, the port recomputes (i + 1) * step; for angle 15 the 30 table indices per circle are identical (exact x87 emulation with 64 and 53 bit mantissas), positions can differ by 1 ulp.
