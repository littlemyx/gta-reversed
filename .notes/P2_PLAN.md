## 2. Design

### 2.1 The trait (slice P-2a, new `source/game_sa/FileRecord.hpp`)
```cpp
namespace notsa {
template<typename T> struct FileRecord;                         // specialise next to T; absent => T is its own file layout
template<typename T> concept HasFileRecord = requires { typename FileRecord<T>::Type; };
template<typename T> constexpr size_t FileSizeOf = HasFileRecord<T> ? sizeof(typename FileRecord<T>::Type) : sizeof(T);
}
// FileRecord<X>: using Type = X_File; static Type ToFile(const X&); static void FromFile(X&, const Type&);
```
`CGenericGameStorage::SaveDataToWorkBuffer<T>(const T&)` / `LoadDataFromWorkBuffer<T>(T&)` / `LoadDataFromWorkBuffer<T>()`:
```cpp
#ifdef NOTSA_PORTABLE
  if constexpr (HasFileRecord<T>) { auto r = FileRecord<T>::ToFile(d); return SaveDataToWorkBuffer((void*)&r, sizeof(r)); } else
#endif
  { static_assert-guard...; return SaveDataToWorkBuffer((void*)&d, sizeof(T)); }
```
Guard (both builds, compile-time only): `!is_pointer_v<T> && !is_same_v<T,long> && !is_same_v<T,unsigned long>` (on Darwin these are `size_t`/`ptrdiff_t`/`intptr_t`; on MSVC `long` is 32-bit and still allowed there => write the guard as `sizeof(T) <= 4 || !integral || (T is not long/unsigned long)` guarded by `sizeof(void*) == 8` so MSVC sees nothing). The same guard goes into `RwStreamRead<T>` (RenderWare.h:76) and `notsa::File::Read<T>/Write<T>` if present.
Raw `(void*, int32)` overloads stay for byte buffers.
Why not (c) "serialiser in both builds": for the 13 structs the exe also writes uninitialised pointers / padding, so byte-identity of a save is not defined; and `CPed::Save` etc. are hooked reversed functions, so any code-byte change needs a wine A/B per TU for no portable gain. (b') keeps MSVC code bytes untouched; the in-both-builds static_asserts give the equivalence proof at compile time.

### 2.2 `layout_diff` gate (slice P-2a, new `tools/portable/layout_diff.py`)
For every struct in `.notes/reports/MAC-P1-file-structs.tsv` (+ each new `*_File`): dump `-fdump-record-layouts-complete` under `--target=i686-pc-windows-msvc` and `--target=arm64-apple-macos15`, compare size, per-field byte offset, bit-field bit offset and width. Required: all `*_File` records and all FILE structs that "pass" are identical. **This also audits the 115 FILE structs that pass the size census**: equal size does not imply equal bit-field layout (MSVC opens a new storage unit when the declared type size changes, Itanium does not; candidates: tRadarTrace, CPathNode, CPickup.m_nFlags, tBinaryIplFile, IplDef, CObjectSaveStructure, tReplay* flags, 2dEffect stream data). Any diff found there becomes an extra `*_File` row.

### 2.3 Assert policy after each fix
The in-memory class gets `VALIDATE_SIZE/OFFSET` (x86 only, compiled out in portable); the new record gets `VALIDATE_SIZE_FILE/OFFSET_FILE` (enforced everywhere). The 9 `VALIDATE_*_FILE` lines in Scripts/Commands/Ported/Group{05_08,13_15,16_17a,16_17c,20a,24a,24b,25_26a}.cpp (+ headers) are turned back into plain `VALIDATE_OFFSET/SIZE` in a separate one-line-per-file commit (announce in PORTABLE_SYNC; low conflict risk, they are top-of-file asserts).

## 5. Order and parallelism
Wave 1 (3 agents): **a**, **i**, **j** (i and j do not use the trait). Wave 2 (after a lands; <= 5): **b**, **c**, **d**, **e**, **f** (d needs b only for the prefix line: land b first or let d change that one line itself). Wave 3: **g**, **h**. Wave 4: **k**.
Shared-file risks: `GenericGameStorage.h` and `FileRecord.hpp` are touched only by a; each later slice specialises the trait in its own struct's header (no common include list). Group*.cpp assert lines only in g. Matrix.h only in c.

## 6. Risks / open points
* MSVC-neutrality of `if constexpr` in an already-instantiated template is expected to be code-identical; verify on Radar.cpp and Pickups.cpp first (wine A/B) before the pattern is reused.
* Bit-field layout equality is unproven for the "passing" FILE structs; layout_diff (P-2a) is the first thing to run, its result can add 1-3 slices.
* Original-exe save compatibility is a nice-to-have, not a requirement (goal = behavioural port). The records are written byte-compatible with the exe wherever cheap (pointer slots 0 except `m_BaseIP`), so the real Windows `.b` fixture is a strong end-to-end check but is not blocking.
* The standalone Win32 run exe (detached globals, stream D) places `ScriptSpace` at its own address, not 0xA49960: saves it writes today already carry non-exe `m_BaseIP` values; harmless because BaseIP is diagnostic only.
* `CGenericGameStorage` work buffer is 50 KiB (`BUFFER_SIZE`); no record grows beyond the x86 file size, so no buffer logic changes.
* Not decided here (belongs to P-3): whether other typed `SaveDataToWorkBuffer(globalVar)` calls with `bool`/enum/`uint32` globals are exact; the P-2a guard + layout_diff cover the 64-bit hazards, not semantic endianness.
