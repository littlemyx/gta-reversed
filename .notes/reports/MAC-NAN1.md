## Tool / harness changes
* `fpe_traps.cpp`: the log now prints the trapped insn and its Rn / Rm (float + double) = tells NaN-in from NaN-made at a glance; more forms emulated (FCVT{N,P,M,Z}{S,U} to W/X, FCVTZS fixed point, scalar-SIMD FCVTZS/U, FABD, vector FCMGT/FCMGE reg), so the masked ~2 ms window is gone: un-emulated in the final intro run = 1 (frsqrte), was ~140 per run. Whitelist entries for sites 16 and 17.
* `Fp.h` `Ftol64` (NOTSA_PORTABLE only, Win32 text identical): the range guard is an integer exponent test (an ordered float compare `fcmpe` of a NaN raises FE_INVALID) and, on arm64, the conversion is an inline `fcvtzs` that cannot be hoisted above the guard (clang had turned the guard into `fcvtzs; csel`, i.e. a speculated out-of-range conversion = the trap). Result values unchanged (host test portable.ftolcast 1.8M checks passes). Effect: no NOTSA_FTOL site (911 of them) raises FE_INVALID for guarded junk any more.
* Harness (the reason several runs of mine did not start a game): the front-end cursor follows the REAL pointer and the machine was in use (pointer at 830,493; the game also warps it itself on menu entry) -> 4 Returns opened Controller Setup. Fixes: (1) `SDLWrapper.cpp` (portable): a scripted run (NOTSA_STANDALONE_INPUT set) ignores real mouse motion (`which != 0`), `NOTSA_STANDALONE_REALMOUSE=1` restores it; (2) `mac_boot_run.sh`: routes whose menu preamble is `until:menu / wait / key:return` get `mouse:636,290` (Start Game) in a per-run copy, the `key:up` preambles are left alone; (3) `tools/portable/play1/park_pointer.py` (warp to (5,5) now and for N s) called by `stab_run.sh` and the fptrap run.sh. All routes: "Loading the Game" 139-144 lines.
