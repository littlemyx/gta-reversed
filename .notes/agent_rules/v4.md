# Agent rules v4 — from 2026-10-21 (git tag `agent-rules-v4`)

Version: v4. Base: everything in `v3.md` (and through it v2/v1) applies unless changed below. Roll back: write `v3` into `CURRENT`.
Why: on 2026-10-21 two regressions reached C:\gta-play although every oracle row was green — a new-game crash (old script-loop bug
exposed by layout shifts, .notes/reports/NEWGAME-CRASH.md) and "no traffic / no police" (a correct MarkRegionsForCoors fix whose
readers still used the old index layout, .notes/reports/REGRESS-POLICE.md). Oracle tests never boot the game.

## Changes vs v3
1. **Orchestrator gate** = run_all_tests + Release build + `soak.sh` (NOVSYNC, 3 min, new game) on every landing, plus
   `gameplay_regress.sh` (GR_SKIP=render_firststart) at least once per day and after any fix touching scripts, streaming, population,
   paths, wanted/police or the main loop. C:\gta-play is refreshed only after a clean soak. (Script: the orchestrator's gate.sh.)
2. **Consumer audit (every agent)**: a fix that changes how shared state is laid out, indexed, sized or what a value means (globals,
   arrays, flags, pool slots, struct fields) must grep every reader and writer of that state and bring them to the exe's convention in
   the same series of commits — list them in the report. A row that passes on the function alone is not enough.
3. **Agents whose fixes touch gameplay code run a game check before landing**: `soak.sh <their build> 3` with NOVSYNC (≈3 min),
   RESULT OK required; for script/streaming/population/path/police code also the matching gameplay_regress scenario.
