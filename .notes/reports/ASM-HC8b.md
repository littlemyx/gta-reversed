# ASM-HC8b: vector sum-order class (inlined 3-term squared sums)
Checked ~30 hot RYDER_1 functions via an automated scan of the exe for the inline pattern `fld st0; fmul st1; fld st2; fmul st3; faddp; fld st3; fmul st4; faddp` (239 functions with an inline/known helper; 92 inline sites in ~60 non-render functions). Fixed 3 functions (Wanted::WorkOutPolicePresence, ScriptsForBrains::IsObjectWithinBrainActivationRange, Pickup::Update revenue branch); 5c498d09e (ProcessStaticCounter) CONFIRMED correct against exe 0x605650 (loads x,y,z -> zyx; fcomp/test ah,5/jp = strict `<`, NaN resets).
Order statistics (92 inline sites): 59 x,y,z, 33 z,y,x. The order is NOT a global constant: MSVC sums LAST-LOADED component first. Vectors read from memory (fld z,y,x) give x,y,z; difference vectors `(a - b)` computed component-wise (fld/fsub x,y,z) give z,y,x. Rule for the TS port: `(a - b)` squared magnitudes / distances inlined = z,y,x; squared magnitude of a stored vector (move/turn speed, force, torque) = x,y,z; out-of-line CVector::SquaredMagnitude (0x406DA0) / Magnitude (0x4082C0) = x,y,z. 2-term sums (Magnitude2D) are order-independent. Check each site (e.g. ProcessCollision's diff is x,y,z because it loads z first).
