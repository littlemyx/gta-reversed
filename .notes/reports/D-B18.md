## Decision item: `CTaskSimpleFight::GetComboFlagsLo` and `C_PcSave::DefaultPCSaveFileName` (0xC16F34)
Exe asm (`gta_sa_compact.exe`, 0x624A40 `CTaskSimpleFight::ChooseAttackAI`):
```
624a44 mov al, [esi+0x24]        ; m_nComboSet (int8)
624a47 movsx ecx, al
624a4a sub ecx, 4
624a4d imul ecx, ecx, 0x88       ; (set-4) * sizeof(CMeleeInfo)
624a55 mov bl, [ecx + 0xC17154]  ; 0xC170D0 (m_aComboData) + 0x84 (m_wFlags, low byte)
```
So the original really indexes **before** the array, no clamp, for set < 4: it is original behaviour, not a port bug (the port reproduces it byte for byte; `GetComboFloatRaw` for `IsTargetInRange` 0x61D6F0 likewise, base 0xC1710C). The sets that reach it: `m_nComboSet` is -1 (ctor), 0 and 1 (assignments; `GetAvailableComboSet` returns 0 for "no set" and the AI then calls ChooseAttackAI); sets 2 and 3 are never assigned. With sizeof(CMeleeInfo) = 0x88 the bytes read are:

| set | flags byte (0xC17154 + k*0x88) | float (0xC1710C + k*0x88) |
|---|---|---|
| -1 | 0xC16EAC = `CGenericGameStorage::ms_SaveFileName`[0xF4] | 0xC16E64 = ms_SaveFileName[0xAC] |
| 0 | 0xC16F34 = `C_PcSave::DefaultPCSaveFileName`[0x1C] (the census stray) | 0xC16EEC = `CGenericGameStorage::ms_WorkBufferPos` |
| 1 | 0xC16FBC = DefaultPCSaveFileName[0xA4] | 0xC16F74 = DefaultPCSaveFileName[0x5C] |

In the exe the "flags" of set 0 are therefore a character of the user's save-directory path (`<Documents>\GTA San Andreas User Files\GTASAsf`, offset 0x1C): environment-dependent, and it steers the AI's choice of moves (tests of bit 1 / 0x40). Not provably unused (the AI does reach it, census D-B09).

Fix (no masking, the neighbour's value is reproduced): in a detached build `m_aComboData` has its own storage, so the neighbours must be named. `TaskSimpleFight.cpp`: detached-only `ReadBeforeComboData(comboSet, offset, size)` maps the byte offset (relative to `m_aComboData`, decimal displacements 792 / 484 / 440 so that no hex literal of a converted address remains) onto the three neighbouring converted globals (ms_SaveFileName, ms_WorkBufferPos, DefaultPCSaveFileName) and reads `size` bytes little-endian from them; any other combination is `NOTSA_UNREACHABLE` (sets 2/3 are never assigned). Address mode keeps the original pointer arithmetic (`#ifdef NOTSA_GLOBALS_DETACHED` / `#else`, `#line` restored after the block). Hand-checked: set 0 flags = rel -412 + 440 = 28 = 0x1C; set 0 float = rel -484 + 484 = 0 = ms_WorkBufferPos; set -1 flags = -548 + 792 = 0xF4.

Evidence limit: the helper is detached-only code and none of the soak/census routes reached a melee AI ped with set < 4 (no touch of 0xC16Fxx / 0xC16Exx in the census runs below), so it was compiled and statically verified, not exercised at run time. The old stray cannot recur: after the conversion nothing reads the old image address.
