### Real bug found by the image comparison (fixed)
`aBikesDescs` (AnimAssocDescriptions.h, 0x8A7F70) had 12 entries, the exe's array has **15**: the groups bmx / mtb / choppa (15 animations each) read descriptors 12..14
(`ANIM_ID_BIKE_BUNNYHOP/PEDAL/SPRINT`, flags 0x1018 / 0x1032 / 0x1032). The source read three descriptors past the end of a 12-entry array.

### New verification mechanism (pointer tables)
Pointer-bearing literal tables cannot be compared byte by byte (every pointer differs). `source/standalone/GlobalsVerifyTables.h` (not in the PCH): a TU registers a
`notsa::globals::TableCheck` under `#ifdef NOTSA_TABLE_CHECKS` (detached + NOTSA_VERIFY_GLOBALS only); the checks run right after the boot dump and append `# TABLE` lines to the
dump file; `verify_globals.py` prints `table checks: N, ok, differ` and fails on a difference. They compare against the **pristine `original_data.bin` read from disk**, not the mapped
image: `Fixups::ApplyToDataImage` patches ASCII text whose dword looks like a code pointer ("strip_B" contains 0x425F70), which made the first anim check fail on a false difference.
4 checks: sectionNames (11 strings), pedIds (13 rows), vehicleDescs (12 tables, 388 rows), anim definitions (118 headers + 1959 names + 1959 descriptors + 27 spare definitions zero).
`codemod_globals.py --check-converted` exempts `NOTSA_TABLE_CHECKS` blocks (they read the image by its original addresses on purpose). standalone_deviations.tsv got 4 whole-global
rows for the pointer tables (the check covers their content).
