## Fixes (all behind `#ifdef NOTSA_PORTABLE`; `tools/portable/w0a_guardlines.py check` TEXT OK for every touched shared file: VehicleModelInfo.cpp, VehiclePool.h, Pool.h, Vehicle.cpp, Ped.cpp, Object.cpp, Event.cpp, Task.cpp, FxMemoryPool.cpp, Streaming.cpp, Placeable.cpp, SDLWrapper.cpp; so the Win32 MSVC TUs are text-identical and no wine cl.exe A/B is needed)
Commits on portable/main (pushed to fork): e15911df (GetWheelPosn, FxMemoryPool, streaming OOB read, spawnmany guard, cutstat, routes), ae6555c8 (vehicle pool slot + alloc-size checks), e3b558d7 (matrix eviction guard, poolstat matrices) + the report commit.
Consumer audit: GetWheelPosn: only SetupSuspensionLines and callers of the non-local plane path read the temp matrix (copy size now = the RwMatrix it is copied into). Vehicle pool: slot stride is used only by CPool index <-> pointer maths (GetIndex / GetAt / IsObjectValid, all derived from sizeof(StorageType)), pool refs / saves / replay are index based; `GetObjectSize()` has no caller. FxMemoryPool: `m_nSize` readers = none besides Exit (frees m_pData). Matrix list: callers of AllocateMatrix tolerate a null m_matrix only through GetMatrix (null deref as before, now logged).
Win32 note for the Windows host: PORTABLE_SYNC.md entry [mac] 2026-10-25 (GetWheelPosn memcpy size is a real 72-into-64 overrun on x86 too; vehicle pool slot size vs CPlane).

## Method notes
* ASan build: system malloc only (the game's pools are one big block each, so slot-to-slot overflows inside a pool are invisible to ASan; that class was found by the replay crash + sizeof table: CAutomobile 2976, CPlane 3136, CHeli 3128, CBoat 2488, CBike 2544, CBmx 2584, CTrain 2192, CQuadBike 3032, CMonsterTruck 3000, CTrailer 3088).
* `NOTSA_MOVLIST_CHECK` diagnostic (moving list items vs pools) was written, found nothing at Process / Remove entry (the corruption is in the vtable of a live object, not a stale list item) and was removed again.
