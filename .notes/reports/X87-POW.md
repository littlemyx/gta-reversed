# X87-POW - x87::pow = the exe's CRT _CIpow

* `_CIpow` 0x822130 (x = ST1, y = ST0): `__sse2_available` (0xC9C400, set by the CRT start-up on every SSE2 machine) and MXCSR / x87 CW all masked -> jump 0x829B80 -> body 0x829B99 (MSVC libm SSE2 kernel); else the old x87 path (0x82218D, fyl2x/f2xm1, not modelled). The kernel: m*2^e, log2(m) from 3 reciprocal tables (T1/T2, T3/T4, T5/T6) + polynomial, v = y*log2 x split hi/lo, k = round(128 v), result 2^(k>>7) * E2[k&127] * (1 + p(r)); all plain IEEE double SSE2 ops, special cases (0, denormal, negative, inf, nan, y = 0/inf/nan, over/underflow) before the matherr hook (errno omitted).
* Port: `source/game_sa/Core/X87Pow.h` (+ `X87PowTables.inc` generated by `tools/standalone/gen_x87_pow_tables.py`), instruction-by-instruction with the exe addresses as labels. Win32 /arch:IA32 uses SSE2 intrinsics (no x87 at PC24), portable plain doubles (-ffp-contract=off).
* Oracle: `x87_oracle_test` rows "CRT _CIpow 0x822130 vs x87::pow" (random, ts-like, wide incl. denormal/huge/random bit patterns, 33x33 special-value grid), 100000 cases each: 0 mismatches. The host UCRT x86 `std::pow` is the same kernel (0 / 100000 on ts-like operands), so the Win32 result of the switched sites is unchanged; the gain is host independence and the portable builds.
* Sites: `.notes/asm_sweep/POW.tsv` - 66 double-operand sites switched; 60 float-overload sites left (follow-up X87-POW-FLOAT), rest comments / no-exe-pow squares.
* Tests: StandaloneRelease + StandaloneRW build clean; wave2_oracle_test 1142 functions 0 mismatches; combat regress PASS=14; soak 6 min OK 0 errors; PortableWin64 /Zs compile of the 22 touched TUs: 0 errors.
