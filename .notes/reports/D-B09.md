## Census environment: kernel writes vs re-arm (cost 3 censuses)
Three census runs with the 110 s start wait crashed at the first mission script (`GET_RANDOM_ICE_CREAM_CUSTOMER_IN_ZONE` NotImplemented from a thread at the mission block) with and without poison, also on the stashed B10 exe. A plain windowed soak of the same exe/route passed (RESULT OK, 14,200 frames at 30 fps), so it is the census, not the port: ImageDiag re-arms (PAGE_NOACCESS) all image pages every 15 s, and a kernel-side `ReadFile` into a protected page fails (documented caveat in ImageDiag.cpp). The mission script is loaded into 0xA7A6A0.. ~0.6 s after `CTheScripts::Init` zeroed the pages, and with the fixed route the re-arm tick fell in between every time (same phase each run); B07V's 20 s wait had a different phase. Route with `wait:101000` (new game load 3 s clear of a re-arm tick) ran clean. Recommendation for the census tooling: leave the script space unprotected or make the load immune (not changed here).

## Soak environment (not a port finding, recorded because it cost 3 soak runs)
The first three B09 soaks (stashed exe, default route) ended `RESULT: FAIL` with 0 errors/exceptions but never left the main menu: on this host the main menu appears ~75 s after start (the splash/loading screens are frame-count loops at 12.7 fps, vsync-locked Present on the current 2560x1600 display; B07V ran on a 3840x2160 display at ~30 fps), while `soak_route.txt` waits a fixed 20 s before clicking, so the injected clicks hit nothing and the pointer stayed on OPTIONS.
Fix used for my runs: private copy of the route with `wait:110000` (the WINDOWED agent's `until:menu` is the proper fix, uncommitted at the time). No tool was changed by me. The three failed runs also showed 0 exceptions with poison on. Windowed (WINDOWED agent's mode, soak.sh default now) runs at 30 fps and needs none of this.
Other findings: (a) a link of `build/StandaloneDetached/bin/gta_reversed.exe` failed once with LNK1201 (cannot write the pdb) while another process held it; moving the old pdb away fixed it. (b) `soak.sh` leaves a stale `gpu.lock` if its caller script dies after the report: I removed my own stale lock once (no exe was running).
Git note: the codemod writes CRLF into the working copy on Windows (git normalises to LF at commit: `w/crlf i/lf`), the committed diffs are line-exact.
