# MAC-RR2 report (2026-10-24)
Result: native RR build is now self-deterministic. 900-frame route: 12 + 20 plain runs and 8 runs with MallocScribble/MallocPreScribble: all traces byte-identical (md5 ffdb1473...); 3000-frame route (60 s virtual): 4/4 identical; no NaN lines, no crash. Pre-fix control (same binary, patch reverted): 8 runs -> 5 distinct traces, 4 with the 84-line NaN diagnostic.
Root cause (F6): rtanim.cpp RtAnimInterpolatorSetCurrentAnim stored keyFrame1/2 pointers into interp frames of the game's scheme, which are 0x1C bytes {q,t} with no header: on LP64 the two pointers (16 B) overwrite the whole quaternion with address bits; the ped constructor's first UpdateRpHAnim reads it. On x86 the same stores hit q.x/q.y only (floats ~1e-38, benign). Details RR_PLAN.md 9.7, PORTABLE_SYNC.md.
Second bug: operator new override in statehash.cpp -> Active() -> Cfg() static -> recursion (abort at startup of every RR build since 1eb6b3cb).
Changes: source/standalone/rw/rtanim.cpp (#ifdef NOTSA_PORTABLE guard on own lines, Win32 text identical), source/portable/statehash.cpp (portable-only), tests/portable/rr2_setcurrentanim_test.cpp + tools/portable/run_rr2_anim_test.sh (+ portable_tests.cmake: portable.rr2, portable.rr2.mutate; run OK, mutant caught).
Audit: blend/add/mulRecip key frame callbacks (StdFrame 48 B on LP64) are never invoked by the game (no RpHAnimHierarchyBlend/Add in hanim.cpp); anim key frame stride is consistent (sizeof(RpHAnimKeyFrame) in memory, 0x24 in the stream); keyFrame pointers are not read anywhere else in game code; NaN guard in CPhysical::RemoveAndAdd not needed now (crash was the NaN prop).
Not done: wine/MSVC code A/B (Win32 preprocessed text of rtanim.cpp is identical by construction: the added lines are inside #ifdef NOTSA_PORTABLE); F5 (CBike member init) still only pinned by zeroed pool slots.
