## The 1-in-60 artefact: stale x87 stack entries

Instrumented full run (print of `CTimer::ms_fTimeStep`, MXCSR, x87 CW / tag word in the port lambda): ts = 0, so `maxUnits` = 0; case 1 has cmd.y = -53.17, moveDir.y = -113.04, delta < -0 so the exe must do `cmd -= 0` (unchanged) - but it
stored -113.04. At that point the x87 tag word was F596 (**6 stale entries on the register stack**; the filtered runs, where no earlier row left entries, pass). The exe function pushes 3 values on that path
(`fld max; fld delta; fld st(1)`), the third overflows the stack, the masked invalid-operation produces QNaN "indefinite", both compares are unordered and the exe takes the assignment path. Real calls never see this: the game's
functions leave the x87 stack empty. The entries come from earlier rows (an exe function that faulted mid-way and was unwound by SEH, or a leaking row); the number of leaked entries changes along the run, which is why the original note saw
1 of 60 and only in the full run.

Fix in the harness (`tests/standalone/wave2_oracle_common.inc`): `CleanX87()` (fnstcw / fninit / fldcw, control word and MXCSR kept) before each side of every case in `GuardedCall`. Full run before: Duck PC24 1 mismatch; after: 0 for all 1142 rows.

## Added coverage
`tests/standalone/wave2_oracle_edge.inc` (hand-maintained, called from `TestW2Edge`): `ControlDuckMove` / `ControlGunMove` with the values the x87 compare logic treats specially for the direction (NaN, +-inf, +-0, 0.1, 0.9, +-1, 3e38) and
for `CTimer::ms_fTimeStep` (0, -0, powers of two, negative, +-inf, NaN), 400 cases each. Time steps are restricted to values whose product with 0.07f is exact: the exe keeps `ts * 0.07f` unrounded in the x87 register, which
differs by one ulp in the CRT-default 53-bit mode (PC53 only; the game runs in the 24-bit mode, PC24 had 0 mismatches for every ts value) - a precision-mode artefact, not a port difference.

## Mutation check
Duck reverted to the old chain: edge row 59 / 400 fail. Gun std::clamp: generated row 1 / 60, edge row fails (clamp asserts on NaN / negative bounds). Facial exchange inline: 99 / 6000. Harness `CleanX87` removed: Duck row 1 / 60 in the full run (before/after of the same binary).
