Fixes (exe range, one line each):
- CFont::InitPerFrame (0x719800-0x719839): the exe clears the outline SIZE byte (0xC71A9B), the outline byte (0xC71A9C) and the shadow byte (0xC71A96); the port wrote 0xC71A9C twice and never cleared 0xC71A9B, so a SetEdge outline leaked into the next frame's text that did not call SetEdge. Also RenderState.m_wFontTexture = 0xFFFF (was 0).
- CFont::GetTextRect (0x71A620-0x71A6F5): right-aligned rect.right = x + 4.0 (port stored x, so the background box of right-aligned text was 4 px too narrow); centre right = (size*0.5+4)+x and bottom = ((h*lines)+y)+4 (association); lines are taken as movzx al; ProcessCurrentString runs first. CFont::GetHeight (shared with PrintStringFromBottom 0x71A820) = (y*32)*0.5 + (y+y), as every inline copy in the exe (port: (y*16+y)+y).
- CFont::PrintString (0x71A700-0x71A810): the background pass copies r,g,b only of m_Color into RenderState.m_color (alpha untouched).
- RenderBuffer::StopStoring (0x7077A0-0x7077F8): the index bias loop is `n < total` (jl); the port's `<=` also biased the first unused index slot.
- CDebug::DebugDisplayTextBuffer (0x532260): the exe function is a bare `ret`; the port set about ten CFont globals (style, scale, colour, drop shadow, centre size, background, ...) and flushed the font buffer (DrawFonts) at each of its 3 call sites every frame. It now returns early when the (never filled) debug list is empty.
- CAEVorbisDecoder::Initialise (0x5024D0): no channel-count check in the exe (kept under FIX_BUGS); a user track shorter than 7 s also clears m_bInitialized. FillBuffer (0x502470): the exe has no mono handling (the port halved the read and duplicated samples); kept under FIX_BUGS.
- CAEWaveDecoder (0x5032B0 / 0x5032A0 / 0x503360 / 0x5033C0): the exe reads a fixed 44 byte header and accepts 16 bit STEREO only (data at 0x2C), FillBuffer is a pass-through. GetStreamPlayTimeMs = (pos-0x2C)/(sampleRate*4)*1000 in float; SetCursor = ftol((pos*0.001f)*(sampleRate*4)+44.0) rounded up to even, seek from the start. The port's chunk-searching parse / mono expansion are kept under FIX_BUGS only; its integer `pos * sampleRate / 1000 * blockAlign` wrapped for positions beyond ~97 s (also fixed in the FIX_BUGS variant with 64 bit math).
