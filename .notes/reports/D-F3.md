# D-F3: the image machinery is gone from the run build (Windows, commits d960635a, b53ee4d7, 10cdb3f9)

## 1. What the run exe is now
`StandaloneRelease` / `StandaloneRW` (every `GTASA_STANDALONE=ON` preset) build an exe that needs **nothing of the original exe at build or run time**: always detached globals (`NOTSA_DETACHED_GLOBALS` is defined for the exe target, the `GTASA_DETACHED_GLOBALS` option is gone), no data image, no 9.1 MB placeholder, no `/BASE:0x400000 /FIXED`, no extraction step, no files next to the exe. It is an ordinary relocatable image: default base 0x400000, `/DYNAMICBASE` (ASLR on, DLL characteristics 0x8140), `.reloc` 654 KB. `standalone.log` starts with `image base 0x00A80000 (ASLR on, size 0x13F0000)` (the loader really moves it).

## 4. Base address / ASLR decision
No code relies on a fixed address any more (census 0 touches, preprocessed scan: no exe address in active code, section 5), so the run exe uses the **default base with `/DYNAMICBASE` (ASLR on)**. It really relocates (base 0xA80000 in the logs); this matches plan section 7 ("after F3 the exe is a normal relocatable image"). Behavioural detail recorded in `docs/STANDALONE_FIDELITY.md`: the original is non-ASLR at 0x400000, so absolute code/data addresses and (for ASLR-opted-in processes) the heap/stack layout differ per run; only a bug that reads uninitialised heap memory or orders by pointer could notice (pools are index based, none known). `-DGTASA_ASLR=OFF` restores the fixed 0x400000 load (relocations stripped) for reproducible debugging. The 15-minute soak and the passing 3-minute soak ran with ASLR on. `.map` offsets are module-relative now (`image base` line in standalone.log; the sampler's "profile" addresses are absolute VAs).

## 7. Notes / leftovers
* `GTASA_ORIGINAL_EXE` stays in the presets and CMake (optional now, only checked for existence when set): removal is G1.
* Name debt: `source/standalone/Fixups.*` and namespace `Fixups` now hold only logging/diagnostics (the plan said `Log.cpp`; a rename touches the unit tests' stub files, left for a rename slice).
* The tests' empty `Fixups::RegisterFunction/RegisterUnverified` and `RHManager::AddHookToCategory` stubs are dead now (harmless; nothing declares them).
* `tools/standalone/windows/startup_probe.py` (and any tool that `ReadProcessMemory`s original VAs such as gstate 0xC8D4C0) cannot read a detached exe: not an F3 regression (true since A2); use the log timestamps instead.
* Mac/Wine and ClangCL presets were not run here. Scratch (disposable, not in git): `C:\gta-scratch\df3\*`, `C:\gta-soak-df3`, `C:\gta-boot-before`, `C:\gta-boot-after`, `C:\gta-census-df3-out`.
