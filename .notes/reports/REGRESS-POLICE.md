# REGRESS-POLICE - police never respond to a wanted level (gameplay_regress combat FAIL=3)

Rules v3, Windows, 07:16-08:37. Worktree regress-police from origin c5d6918b.

- **Symptom** (HEAD 2e75ef99): at wanted level 2 in Idlewood no cop/law car ever appears, nobody hurts CJ (police_arrive / police_engage / player_shot_at FAIL). Reproduced on a fresh worktree build.
- **Diagnosis**: temporary counters in CCarCtrl::GenerateOneRandomCar showed `NumRandomCars = NumLawEnforcerCars = 0` for the whole run and CCarCtrl::GenerateCarCreationCoors2 returning false on ~all calls (2621 of ~2900 in 70 s) - there were no path nodes around CJ at all, so not only police: no traffic. Police are the part the scenario observes.
- **Culprit**: 1ef99baa `CPathFind::MarkRegionsForCoors 0x44DB60` (2026-10-20). Its change is right: the exe stores the flag at `lea edx,[ebx+ebp*8+0x96EFD0]` = ToBeStreamed[xRegion*8 + yRegion] (0x44DC85), the port wrote [y*8+x]. The commit message claimed "the same layout CPathFind::UpdateStreaming reads", which is false for the port: its UpdateStreaming / LoadSceneForPathNodes used the flat flag index as the area (node file / model) number (y*8+x, = CPathFind::FindRegionForCoors 0x44D830 `lea eax,[esi+eax*8]`). The port was self-consistent before (two transpositions cancelled); after the fix the area streamed around Idlewood (x=6,y=1) was 49 instead of 14. Not a fixture artefact: the oracle row matches the exe, the two consumers were not ported to the exe layout.
- **Exe evidence**: UpdateStreaming 0x450A60 loop 0x450CF0: `mov al,[esi+ebp*8+0x96EFD0]` (flag, ebp = x outer, esi = y inner), `lea edi,[ebp+0x63A7]` + `add edi,8` per esi (model = 0x63A7 + x + y*8), node pointer stepped by 0x20 per esi (area x + y*8); load-area rect marking 0x450CA5 `lea edi,[esi+ebx*8+0x96EF90]`; LoadSceneForPathNodes 0x44DE39..0x44DE60 same shape.
- **Fix** (one commit, 729926c4): UpdateStreaming (flag loop, rect marking incl. ToBeStreamedForScript) and LoadSceneForPathNodes translate flag index [x*8+y] <-> area y*8+x, x outer / y inner like the exe. No oracle row (the loop drives streaming requests); verified by the scenario.
