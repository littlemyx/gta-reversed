# Agent rules v5 — from 2026-10-24 (git tag `agent-rules-v5`)

Version: v5. Base: everything in `v4.md` (and through it v3/v2/v1) applies unless changed below. Roll back: write `v4` into `CURRENT`.
Do not edit this file once tagged; changes → `v6.md`.
Why (metrics.tsv 2026-10-23/24):
- Gate run_all_tests took 1.5–2 h instead of ~30 min whenever 2 agents built in parallel; agents lost 35–45 min waiting on build.lock / gpu.lock.
- RD-ARM and RD-NOISE could not land because a full run_all_tests did not fit their cap.
- A gate soak FAILED because another agent killed `gta_reversed.exe` by image name during its cleanup.
- Agents were at 1.0–1.6x the token budget.

## Changes vs v4
### Every agent
1. **Never kill by image name** (`taskkill /IM`, `pkill -f gta_reversed`, `Stop-Process -Name`). Kill only processes you started, by
   their Windows pid (`/proc/<pid>/winpid`, `taskkill //F //T //PID`). Scripts you write follow the same rule.
2. **Landing gate for agents** = Release build + the oracle targets you touched + soak (gameplay code) — NOT the full run_all_tests.
   The orchestrator's gate runs the full suite on the merged tree. Land when your part of the gate passes; say what you did not run.
3. **Token budget**: at 200k tokens stop starting new work and land; never exceed 250k.
### Orchestrator
4. **Gate window**: while the orchestrator gate runs (run_all_tests + Release + soak + gameplay_regress), at most 1 agent runs and no
   new agent is started. Start the gate when ≤1 agent is active.
5. Branch-only work (e.g. replay-diff) is merged by the orchestrator right before a gate, and the gate covers it.
